# Local Floci environments

The Docker Compose application runs at http://localhost:8080. Start it with
`bash floci/docker/up.sh` from WSL. The launcher provisions Cognito, S3, and
four RDS instances through CloudFormation, reads their generated IDs and
database endpoints, then starts Compose. It writes the local connection values
to the ignored `floci/docker/.generated.env` file. Use this launcher after
recreating Floci; plain `docker compose up` cannot discover the generated
values. `npm run dev` also uses this launcher and connects its local backend
processes through Floci's published RDS proxy ports.

The separate EKS-mode Floci instance runs at http://localhost:4567. Run
`bash floci/eks/up.sh` from WSL to provision its own four RDS instances and
k3s cluster, import the application images, apply the Kubernetes manifests,
run migrations, and forward the ingress to http://localhost:9090. The script
writes its kubeconfig to `floci/eks/.kubeconfig`. For a rerun with unchanged
images, set `SKIP_IMAGE_BUILD=1 SKIP_IMAGE_IMPORT=1`.

Compose has no PostgreSQL database services, and local EKS has no PostgreSQL
database Pods. Floci implements RDS using emulator-managed PostgreSQL
containers behind its RDS endpoint proxy; those are created by the RDS
CloudFormation stack, not by Compose or Kubernetes manifests. Local RDS
credentials are generated by Secrets Manager. Removing or recreating the Floci emulator
can reset its RDS data.

`infra/relay-auth.yaml` and `infra/relay-storage.yaml` are shared with AWS.
Both local modes deploy the temporary `infra/relay-floci-eks.yaml` template.
Docker mode disables its EKS resources; EKS mode enables them. Its four RDS
instance definitions match `infra/relay-eks.yaml`, including instance class,
gp3 storage, private subnet group, seven-day backups, snapshot policies, and
generated Secrets Manager credentials. The surrounding local VPC and security
group differ from AWS because Floci uses a local Docker network. The temporary
template can be removed when Floci's HTTPS and external plugins support the
full AWS template.

Floci's CloudFormation emulator currently ignores the DB instance's gp3 storage,
seven-day backup retention, and security group properties. The initialization
script applies those values through the Floci RDS API after the stack deploys
and verifies the reported configuration. Floci still uses local PostgreSQL
containers; it does not provide AWS gp3 volumes or RDS backups.

Inspect the local cluster with
`kubectl --kubeconfig floci/eks/.kubeconfig -n relay get pods`.
